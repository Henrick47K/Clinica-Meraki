# Clinica-Meraki

### Autores da equipe: Henrique Duarte Lima, Miguel Ribeiro Fleck, Jonatha Lohan Moreira da Silveira

Checklist da aula 04
Processos de engenharia de software

Participantes: Henrique Duarte Lima, Miguel Ribeiro Fleck e Jonatha Lohan Moreira da Silveira


•	Pelo menos 1 regra de negócio
•	Pelo menos 3 requisitos funcionais (RF)
•	Pelo menos 2 requisitos não funcionais (RNF)
•	Pelo menos 2 histórias de usuário


1 – A) Um profissional não pode possuir 2 agendamentos no mesmo horário.
B) Um paciente não pode possuir 2 agendamentos no mesmo horário.

2 – A) Cadastro do paciente; O sistema deve permitir que a recepcionista cadastre um paciente informando o nome, CPF e telefone.
B) Consulta de horários; O sistema deve permitir que a recepcionista consulte os horários disponíveis em um profissional em uma data especifica.
C) Agendamento de consulta; o sistema deve permitir que a recepcionista agende uma consulta, selecionando paciente, profissional, data e horário disponíveis.

3 – A) O sistema deve apresentar os horários disponíveis em até 2 segundos após a solicitação.
B) O sistema deve estar disponível para utilização durante 99% do horário de funcionamento da clínica Meraki, exceto durante manutenções programadas.

4 – A) Como recepcionista, quero consultar os horários disponíveis de um profissional, para conseguir agendar uma consulta sem conflito de horários.
B) Como recepcionista, quero cadastrar e agendar consultas para os pacientes, para manter a agenda da clínica organizada.
